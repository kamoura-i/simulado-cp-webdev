Checkpoint Simulado — Catálogo de Estudos

Atenção: faça o simulado sem consulta e sem ajuda durante a execução. O objetivo é descobrir o que você realmente consegue construir sozinho antes do CP.

Contexto do case

Você foi chamado para desenvolver um pequeno Catálogo de Estudos. O usuário deve cadastrar recursos de estudo, visualizar a lista, pesquisar recursos, abrir uma página de detalhes e excluir registros. Os dados devem ser persistidos em uma API criada no MockAPI.

📌 Instruções gerais

  1. Gere o projeto usando create-next-app e App Router.
  2. Use componentes funcionais e "use client" quando necessário.
  3. Use Axios para conversar com a API do MockAPI.
  4. Crie commits separados e coerentes durante o desenvolvimento.
  5. Não use localStorage.
  6. Estilização é livre e não é o foco da avaliação.
  7. Comente apenas os blocos importantes, explicando por que o hook ou comportamento foi usado.

📝 O que fazer

Páginas necessárias

  • / — formulário, pesquisa e lista de recursos.
  • /recursos/[id] — detalhes de um recurso específico.

Cada recurso deve possuir

titleNome do recurso de estudo.
categoryCategoria, por exemplo React, Python ou IA.
descriptionDescrição curta do conteúdo.
idIdentificador fornecido pela API.

Funcionalidades obrigatórias

  • Buscar os recursos da API quando a página principal carregar.
  • Exibir estado de carregamento e uma mensagem caso a requisição falhe.
  • Cadastrar um novo recurso e persistir o registro no MockAPI.
  • Excluir um recurso específico da API.
  • Pesquisar recursos pelo título sem alterar os dados originais.
  • Abrir uma rota de detalhes usando o ID do recurso.
  • Atualizar o título da aba do navegador na página de detalhes.
  • Após cadastrar um recurso, colocar o foco novamente no primeiro campo do formulário.
  • Evitar recriações desnecessárias onde fizer sentido, usando os hooks vistos em aula.
Importante: o enunciado não diz em qual linha usar useRef, useMemo, useCallback ou memo. Parte do simulado é reconhecer onde cada ferramenta faz sentido.

🏆 Critérios de avaliação

1
Estrutura e componentização
Projeto organizado e componentes funcionais separados de forma coerente.
2
useState
Estados do formulário, lista, busca, loading e erro funcionando corretamente.
3
useEffect + GET
Carregamento inicial dos dados da API.
4
POST
Novo recurso persistido na API e refletido na interface.
5
DELETE
Exclusão pelo ID na API e atualização correta da interface.
6
Router
Navegação entre a lista e a rota dinâmica de detalhes.
7
Props
Dados e ações passados corretamente entre componentes.
8
Hooks adicionais
Uso justificável de useRef, useMemo e useCallback, além de memo quando apropriado.
9
Estados da requisição
Loading, sucesso e erro tratados na interface.
10
Clareza e Git
Código compreensível, comentários úteis e commits coerentes.

⏱️ Regra do simulado

Faça a primeira tentativa sem ChatGPT, documentação ou código anterior. Se travar, anote exatamente onde. A correção deve avaliar separadamente aprendizado e desempenho, além da nota técnica do projeto.
